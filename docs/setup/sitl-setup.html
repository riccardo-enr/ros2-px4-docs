PX4 SITL Setup

This page covers how to build PX4 firmware, launch the Gazebo SITL simulator, and wire it into the pixi workspace for use with the ROS 2 integration.

Prerequisites

PX4 SITL requires a native Ubuntu build environment. The PX4 source tree is not managed inside the ROS 2 workspace — it lives separately and is built with its own toolchain.

# Install PX4 build dependencies (run once)
git clone https://github.com/PX4/PX4-Autopilot.git --recursive
cd PX4-Autopilot
bash ./Tools/setup/ubuntu.sh
Note

ubuntu.sh installs system packages including gcc-arm-none-eabi, ninja, and Python dependencies. It also installs gz-harmonic (Gazebo) for SITL. Re-run it if a new PX4 checkout changes the required dependencies.

Building and launching

cd PX4-Autopilot
make px4_sitl gz_x500

This compiles the SITL binary and launches both PX4 and the Gazebo GUI. The first build takes ~5 minutes; subsequent builds are incremental.

On launch, PX4 prints its version string (PX4 v1.16.x) and drops into the NuttShell:

nsh>

Confirm the build binary exists:

ls build/px4_sitl_default/bin/px4

Supported vehicle models

All make targets have the prefix gz_. The PX4_SYS_AUTOSTART ID is the airframe number used when launching the binary directly (without make).

Vehicle make target PX4_SYS_AUTOSTART
x500 quadrotor gz_x500 4001
x500 + depth camera (front) gz_x500_depth 4002
x500 + visual odometry gz_x500_vision 4005
x500 + 1D lidar (down) gz_x500_lidar_down 4016
x500 + 2D lidar gz_x500_lidar_2d 4013
x500 + 1D lidar (front) gz_x500_lidar_front 4017
x500 + gimbal (front) gz_x500_gimbal 4019
Standard VTOL gz_standard_vtol 4004
RC Cessna (plane) gz_rc_cessna 4003
Differential rover gz_rover_differential 50000
Ackermann rover gz_rover_ackermann 51000

Supported worlds

Append the world name to the model target, or set PX4_GZ_WORLD:

make px4_sitl gz_x500_windy
# equivalent:
PX4_GZ_WORLD=windy make px4_sitl gz_x500
World Description
default Empty flat plane (used when no world is specified)
windy Empty world with wind enabled
baylands Terrain surrounded by water
aruco Empty world with ArUco marker for precision landing testing
walls Walled arena for collision-prevention testing
lawn Lawn surface for rover testing
moving_platform Moving takeoff/landing platform
Warning

Do not specify gz_x500_default explicitly — PX4 will fail to launch. Use gz_x500 (no suffix) for the default world.

Key environment variables

Set these before calling make or running the PX4 binary directly.

Variable Purpose Example
PX4_SIM_MODEL Spawn a new vehicle model by name gz_x500
PX4_GZ_MODEL_NAME Bind to an existing Gazebo model by name x500
PX4_SYS_AUTOSTART Airframe ID (required when running binary directly) 4001
PX4_GZ_WORLD Override the Gazebo world file windy
PX4_GZ_MODEL_POSE Spawn pose x,y,z,roll,pitch,yaw (metres, radians) 0,2,0,0,0,0
PX4_HOME_LAT Home latitude (degrees) 51.1788
PX4_HOME_LON Home longitude (degrees) -1.8263
PX4_HOME_ALT Home altitude (metres AMSL) 101
HEADLESS Disable Gazebo GUI 1
PX4_SIM_SPEED_FACTOR Run faster/slower than real-time 2
PX4_GZ_STANDALONE Start PX4 only; connect to a separately-running Gazebo 1
PX4_GZ_SIM_RENDER_ENGINE Override render engine (use ogre on VMs) ogre
Note

PX4_SIM_MODEL and PX4_GZ_MODEL_NAME are mutually exclusive. Use PX4_SIM_MODEL to spawn a new vehicle; use PX4_GZ_MODEL_NAME to attach a new PX4 instance to a model that Gazebo has already spawned.

Examples

# Headless, custom spawn pose
HEADLESS=1 PX4_GZ_MODEL_POSE="0,0,0.5,0,0,1.57" make px4_sitl gz_x500

# Run at 2x real-time speed
PX4_SIM_SPEED_FACTOR=2 make px4_sitl gz_x500

# Custom home location (GPS origin)
export PX4_HOME_LAT=51.1788
export PX4_HOME_LON=-1.8263
export PX4_HOME_ALT=101
make px4_sitl gz_x500

# VM with poor OpenGL support
PX4_GZ_SIM_RENDER_ENGINE=ogre make px4_sitl gz_x500

Standalone mode

In standalone mode PX4 and Gazebo run in separate terminals. This is useful for attaching to an already-running Gazebo instance, or for running them on different machines.

Terminal 1 — start Gazebo:

# Download the simulation-gazebo launcher script (once)
wget https://raw.githubusercontent.com/PX4/PX4-gazebo-models/main/simulation-gazebo
python3 simulation-gazebo

simulation-gazebo downloads models and worlds to ~/.simulation-gazebo on first run and re-uses them on subsequent runs.

Terminal 2 — start PX4:

cd PX4-Autopilot
PX4_GZ_STANDALONE=1 make px4_sitl gz_x500

PX4 will print WARN [gz bridge] Service call timed out until Gazebo starts — this is normal. Once Gazebo is up, PX4 connects automatically.

Integrating with the pixi workspace

Store the path to the PX4 source tree as a pixi variable and expose it via the activation environment.

pixi.toml:

[activation]
env = { PX4_AUTOPILOT = "/home/user/PX4-Autopilot" }

[tasks]
px4 = { cmd = "cd $PX4_AUTOPILOT && make px4_sitl gz_x500" }
px4-headless = { cmd = "cd $PX4_AUTOPILOT && HEADLESS=1 make px4_sitl gz_x500" }

Confirming SITL is running

Check EKF and commander state from the NuttShell:

nsh> ekf2 status
nsh> commander status

In a separate terminal, confirm DDS topics appear after starting the micro-XRCE-DDS agent (see DDS Agent Setup):

ros2 topic list | grep fmu

Troubleshooting

ninja: error: unknown target 'gz_x500'

The build tree is stale. Run make distclean then retry:

make distclean
make px4_sitl gz_x500

make px4_sitl gz_x500 fails with missing submodules

The PX4 repo was cloned without --recursive:

git submodule update --init --recursive

Gazebo window does not open

The display is not forwarded or the GPU driver lacks OpenGL 3.3 support. Either set HEADLESS=1, or try the OGRE 1 renderer:

PX4_GZ_SIM_RENDER_ENGINE=ogre make px4_sitl gz_x500

PX4 exits immediately after launch

Lockstep is waiting for a Gazebo clock. Ensure Gazebo is running — the gz_x500 target launches both. In standalone mode, start Gazebo before PX4.

EKF2 ERROR at startup

Normal for the first ~5 s while sensors initialise. If it persists, check that gz-harmonic is installed and the Gazebo sensors plugin loaded without errors.
