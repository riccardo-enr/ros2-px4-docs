Low-Level Offboard Control

Low-level offboard control means bypassing PX4’s position/velocity controllers and sending commands directly to the inner loops. Three levels are available, selected at runtime via a ROS 2 parameter:

Mode control_mode PX4 message What you command
Attitude 1 VehicleAttitudeSetpoint Desired quaternion + collective thrust
Thrust + Torque 2 VehicleThrustSetpoint + VehicleTorqueSetpoint Body-frame wrench
Direct actuator 3 ActuatorMotors Per-motor throttle [0, 1]

Reference implementation: SaxionMechatronics/px4_offboard_lowlevel.

OffboardControlMode heartbeat

PX4 requires a continuous OffboardControlMode heartbeat at ~3 Hz or it exits offboard mode. The active fields must match the command type being sent:

px4_msgs::msg::OffboardControlMode msg{};
msg.position          = false;
msg.velocity          = false;
msg.acceleration      = false;
msg.body_rate         = false;

// mode 1 — attitude
msg.attitude          = true;
msg.thrust_and_torque = false;
msg.direct_actuator   = false;

// mode 2 — thrust + torque
// msg.thrust_and_torque = true; (attitude and direct_actuator = false)

// mode 3 — direct actuator
// msg.direct_actuator = true; (attitude and thrust_and_torque = false)

msg.timestamp = node->get_clock()->now().nanoseconds() / 1000;
offboard_control_mode_pub->publish(msg);

The heartbeat timer and the controller output timer are independent:

// 3 Hz heartbeat
offboard_timer = create_wall_timer(333ms, [=]() { publishOffboardControlModeMsg(); });

// 100 Hz control loop
controller_timer = create_wall_timer(10ms,  [=]() { updateControllerOutput(); });

Frame conventions

PX4 uses NED / FRD (North-East-Down, Front-Right-Down). ROS and most controllers use ENU / FLU (East-North-Up, Front-Left-Up). All setpoints must be converted before publishing, and all odometry must be converted after reading.

See Frame Conventions for the full conversion reference including vector permutations, quaternion transforms, altitude sign, and yaw convention.

Mode 1: Attitude setpoint

Publish VehicleAttitudeSetpoint with a desired quaternion and collective thrust. The PX4 attitude controller tracks the quaternion error.

px4_msgs::msg::VehicleAttitudeSetpoint msg{};
msg.timestamp = node->get_clock()->now().nanoseconds() / 1000;

Eigen::Quaterniond q_ned = rotateQuaternionFromToENU_NED(desired_q);
msg.q_d[0] = q_ned.w();
msg.q_d[1] = q_ned.x();
msg.q_d[2] = q_ned.y();
msg.q_d[3] = q_ned.z();

msg.thrust_body[0] = 0.0;
msg.thrust_body[1] = 0.0;
msg.thrust_body[2] = -collective_thrust;   // NED: downward = negative

attitude_setpoint_pub->publish(msg);

Mode 2: Thrust + torque setpoint

Publish separate VehicleThrustSetpoint and VehicleTorqueSetpoint messages. PX4 uses these directly — no attitude controller in the loop.

px4_msgs::msg::VehicleThrustSetpoint thrust_msg{};
px4_msgs::msg::VehicleTorqueSetpoint torque_msg{};

uint64_t ts = node->get_clock()->now().nanoseconds() / 1000;
thrust_msg.timestamp = thrust_msg.timestamp_sample = ts;
torque_msg.timestamp = torque_msg.timestamp_sample = ts;

thrust_msg.xyz[0] = 0.0;
thrust_msg.xyz[1] = 0.0;
thrust_msg.xyz[2] = -collective_thrust;   // NED sign

// Rotate torque from controller FLU frame to FRD
Eigen::Vector3d tau_frd = rotateVectorFromToFRD_FLU(torque_flu);
torque_msg.xyz[0] = tau_frd.x();
torque_msg.xyz[1] = tau_frd.y();
torque_msg.xyz[2] = tau_frd.z();

thrust_pub->publish(thrust_msg);
torque_pub->publish(torque_msg);

Mode 3: Direct actuator commands

Publish ActuatorMotors with per-motor throttles in [0, 1]. Unused slots must be NaN.

px4_msgs::msg::ActuatorMotors msg{};
msg.control = {
    (float) throttles[0], (float) throttles[1],
    (float) throttles[2], (float) throttles[3],
    std::nanf("1"), std::nanf("1"), std::nanf("1"), std::nanf("1"),
    std::nanf("1"), std::nanf("1"), std::nanf("1"), std::nanf("1")
};
msg.reversible_flags = 0;
msg.timestamp = msg.timestamp_sample = node->get_clock()->now().nanoseconds() / 1000;
actuator_motors_pub->publish(msg);
Warning

Lockstep must be disabled for direct actuator control in Gazebo SITL. Set lockstep: false in the model’s model.sdf and in PX4’s SITL config.

Control allocation (wrench -> throttles)

When using mode 3 (direct actuator), the controller must convert the desired wrench \([\tau_x, \tau_y, \tau_z, T]\) to per-motor throttles. See Control Allocation for the full derivation, mixing matrix, C++ implementation, and x500 parameters.

Topic map

Direction Topic Message type
in /fmu/out/vehicle_odometry VehicleOdometry
in /fmu/out/vehicle_status_v1 VehicleStatus
out /fmu/in/offboard_control_mode OffboardControlMode
out /fmu/in/vehicle_command VehicleCommand
out /fmu/in/vehicle_attitude_setpoint VehicleAttitudeSetpoint
out /fmu/in/vehicle_thrust_setpoint VehicleThrustSetpoint
out /fmu/in/vehicle_torque_setpoint VehicleTorqueSetpoint
out /fmu/in/actuator_motors ActuatorMotors

Note the versioned topic name for VehicleStatus — see version mismatch.

Switching modes at runtime

The control mode can be changed without restarting the node:

ros2 param set /offboard_controller control_mode 2   # -> thrust + torque
ros2 param set /offboard_controller control_mode 3   # -> direct actuator
ros2 param set /offboard_controller control_mode 1   # -> attitude (default)

The OffboardControlMode heartbeat automatically switches its active field on the next publish cycle.
